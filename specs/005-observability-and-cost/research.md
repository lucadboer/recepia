# Research: Observability and Cost Control

## R1 — Tracing setup
- **Decision**: business code depends only on `@opentelemetry/api` (`trace.getTracer("recepia")`); with no SDK registered every call is a no-op (FR-506, FR-516). `src/telemetry/register.ts` is loaded with `node --import` by `pnpm start` and `pnpm perf:smoke`; when `OTEL_EXPORTER_OTLP_ENDPOINT` or `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is set it registers a `NodeTracerProvider` (resource `service.name` = `OTEL_SERVICE_NAME` or `recepia`, `service.version` from package.json) with a `BatchSpanProcessor(OTLPTraceExporter)` (OTLP/HTTP, port 4318), the async-hooks context manager and the W3C propagator, plus `PgInstrumentation` (registered before `pg` is imported — the reason for `--import`). Sampling: parent-based always-on (single clinic). Shutdown flushes the processor (wired into the existing graceful shutdown).
- **Rationale**: standard, vendor-neutral, zero cost when off; `sdk-trace-node` instead of `sdk-node` keeps the dependency set small (no metrics/logs SDKs).
- **Alternatives**: `@opentelemetry/sdk-node` + auto-instrumentations (pulls dozens of packages); HTTP auto-instrumentation (the webhook answers 200 before processing, so per-message root spans are the meaningful unit — added manually).

## R2 — Span model and attributes
- **Decision**: `webhook.inbound` (root per patient message, kind CONSUMER; `recepia.channel`, `recepia.message.id`, `recepia.patient.id`, `recepia.patient.phone_masked`) → `agent.turn` (`recepia.turn.status`, `recepia.prompt.version`, `recepia.conversation.status`, `recepia.conversation.cost_usd`) → `chat {model}` per model call (GenAI semconv: `gen_ai.operation.name=chat`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_creation.input_tokens`, `gen_ai.response.finish_reasons`; plus `recepia.prompt.version`, `recepia.llm.cost_usd`, `recepia.llm.fallback`) → `execute_tool {name}` (`gen_ai.operation.name=execute_tool`, `gen_ai.tool.name`, `recepia.tool.outcome` = ok | rejected | error, `recepia.tool.rejected_by` = unknown_tool | not_offered | foreign_hold | consent | invalid_args | after_handoff, `error.type`; inputs recorded only for `type`/`start`) → `pg.query` (instrumentation, statement text without values) and `outbox.dispatch` (`recepia.outbox.kind`, `recepia.outbox.attempt`, `recepia.outbox.result`). Jobs get roots `job.<name>`. Attribute names are string constants in `tracing.ts` (no dependency on the incubating semconv entry point).
- **Rationale**: the GenAI conventions make traces readable in any backend that understands LLM spans; the `recepia.*` namespace carries domain facts (gate, prompt version, cost).
- **Alternatives**: logging message/response content as span events (forbidden by FR-505).

## R3 — Linking deferred delivery to the turn
- **Decision**: migration 010 adds `outbox_message.trace_context text NULL`; `enqueueOutbox` injects the active context with the W3C propagator into a carrier and stores `traceparent` (NULL when tracing is off). `dispatchOutbox` starts `outbox.dispatch` per claimed row with a **span link** to the stored context; when called inside a turn the span is also a child of the turn (same trace), when called by the background job it is a child of `job.outbox`.
- **Rationale**: links survive retries hours later without forcing all deliveries into one long trace.

## R4 — Logs and personal data
- **Decision**: `pino` (JSON to stdout), level `LOG_LEVEL` (default `info`; `silent` in the test setup unless set). A facade `log` (`debug/info/warn/error/child`) delegates to a module-level instance replaceable by `configureLogger({ destination, level })` for tests. `mixin` adds `trace_id`/`span_id` from the active span. `formatters.log` walks the record and masks any `+?\d{10,15}` sequence in string values (backstop for error messages, e.g. `ConversationConflictError`); `redact` removes `text`, `body`, `content`, `patient_name` keys. Patient identity: `patientPseudonym(phone)` = first 16 hex chars of HMAC-SHA256(phone, `TELEMETRY_HASH_KEY`); without the key a random 32-byte key is generated per process and one warning is logged; `maskPhone` keeps the last 4 digits (`***8888`). CLIs that talk to a human (seed, migrate CLI, conversation release, retention purge) keep plain console output; the service path uses `log` only.
- **Rationale**: pino is the de-facto Node JSON logger and cheap; pattern masking catches what key-based redaction misses.

## R5 — Prompt caching
- **Decision**: (1) `buildSystemPrompt` returns `cacheablePrefixLength` (length of the static block); `LlmTurnInput.systemCacheablePrefix?: number`. The Anthropic adapter sends `system` as two text blocks — the static block with `cache_control: {type: "ephemeral"}` and the dated line — so tools + static instructions are one cached prefix (≈ 1.5k tokens, above the 512-token minimum of Sonnet 5.5). (2) Top-level `cache_control: {type: "ephemeral"}` (automatic caching) caches the growing conversation tail: within an inbound turn every iteration reads the previous one's prefix (2–7 calls per message). Across inbound turns the dated line changes, so only tools + static system are re-read — acceptable; moving the date to an appended mid-conversation `role: "system"` message (model-specific) is recorded as the next optimisation, not done here. 5-minute TTL (calls in a turn are seconds apart). The OpenAI-compatible adapter ignores the boundary (those providers cache by prefix automatically).
- **Rationale**: "one explicit breakpoint on the static system prefix plus top-level automatic caching for the tail" is the documented robust pattern for agent loops.
- **Verification**: one live conversation (≤ US$ 0.02) must show `cache_read_input_tokens > 0` from its second call (SC-504).

## R6 — Usage, pricing and budget
- **Decision**: `LlmTurnResult` gains `model` (served) and `provider`. The pricing table moves to `src/llm/pricing.json` (`evals/lib/pricing.ts` re-exports); `costUsd(table, model, usage)` unchanged. `ConversationState.usage = { inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, costUsd, calls, models: string[] }`, zeros in `emptyState`, legacy rows read as zeros, reset with the conversation. Before each model call the orchestrator checks `usage.costUsd >= budgetUsd` (`AgentDeps.budgetUsd`, default `AGENT_BUDGET_USD` = 0.25) → `escalateToHuman(reason "budget_exceeded", context with cost and budget)`, deterministic reply unless a committed confirmation owns it, status `escalated`. After each call: add usage and cost (unknown price → 0 + one warning; the startup check in `composition.ts` refuses to start when the configured primary or fallback model has no price).
- **Rationale**: checking before the call bounds the overrun to one call (SC-503); the per-conversation unit matches how reception thinks about a patient.

## R7 — Fallback provider
- **Decision**: `OpenAICompatibleLLM({ baseUrl, apiKey, model, timeoutMs })` posts to `{baseUrl}/chat/completions` with `tools` as `{type:"function", function:{name, description, parameters}}`; maps history: system → `role:system`, user text → `role:user`, assistant text + tool_use → `role:assistant` with `tool_calls` (`arguments` = JSON string), tool_result → `role:tool` + `tool_call_id`, thinking blocks dropped; response `finish_reason` `tool_calls`→`tool_use`, `stop`→`end_turn`, `length`→`max_tokens`, `content_filter`→`refusal`; unparsable `arguments` → `{}` (the registry rejects it as invalid arguments); usage `prompt_tokens - cached_tokens` / `completion_tokens` / `cached_tokens`. Errors throw `LlmProviderError{status, transient}`. `FallbackLLM(primary, secondary)` calls the secondary only when `isTransientLlmError(err)` (Anthropic `APIConnectionError`/timeout, status 408/429/5xx/529, `LlmProviderError.transient`), records `recepia.llm.fallback=true` and a span event with the primary error type. Anthropic client gets `timeout` = `ANTHROPIC_TIMEOUT_MS` (default 30 000) so a hung primary falls over. Wiring in `composition.ts` when `FALLBACK_LLM_BASE_URL`, `FALLBACK_LLM_API_KEY` and `FALLBACK_LLM_MODEL` are set.
- **Rationale**: one JSON POST does not justify a provider SDK; never retrying refusals keeps "escalate on doubt" intact.

## R8 — Health endpoints
- **Decision**: `GET /healthz` → 200 `{"status":"ok"}` always; `GET /readyz` → `SELECT 1` with a 1 s timeout → 200 `{"status":"ready"}` or 503 `{"status":"not_ready"}`; exact paths, GET/HEAD only, not logged per request, no auth; `createWebhookServer({ ready })` receives the readiness probe.

## R9 — Retention
- **Decision**: `purgeInactive(pool, now, { olderThanDays = 90, dryRun })` in one transaction: `DELETE FROM conversation_state WHERE updated_at < cutoff`; `DELETE FROM outbox_message WHERE status IN ('sent','failed','cancelled') AND created_at < cutoff`; audit `retention_purged` (actor `system`, payload `{ conversationStates, outboxMessages, olderThanDays, cutoff }`) — dry run counts with `SELECT` and writes nothing. Scheduled daily (`RETENTION_INTERVAL_MS` = 24 h) in `startJobs`; CLI `pnpm retention:purge [--dry-run] [--days N]`.

## R10 — Evals and perf
- **Decision**: metrics gain `cost.cacheHitRatio` = cacheRead / (input + cacheRead + cacheWrite) and `cost.uncachedEquivalentUsd` (the same tokens priced as plain input, so SC-504's comparison needs no extra paid run), and the report/README block show them; the live CLI prints the estimated cost of each execution and the running total; `--provider anthropic|openai-compatible` selects the adapter (report records `provider`). `perf.yml` adds a `jaegertracing/jaeger` service and runs the smoke with `--import ./src/telemetry/register.ts` and the OTLP endpoint, so the p95 budget is measured with a real exporter.

## R11 — Live spend under a small credit (owner, 2026-10-07)
- **Decision**: no live call until caching is implemented; then one live conversation to verify caching (≤ US$ 0.02); the first live baseline of feature 004 runs afterwards with `--repetitions 1 --cap-usd 1` (≈ US$ 0.5 with caching) in a follow-up PR; anything above US$ 1 is asked first. The weekly CI live job stays inert (no repository secret) until the owner funds it.
