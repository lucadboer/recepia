# CLAUDE.md — dental appointment booking agent

## Project context

A WhatsApp agent that **books routine appointments autonomously** for a dental clinic, writing them
to the clinic's calendar (Google Calendar), and **escalates to a human** everything out of scope.
It is sold on no-show reduction. The project is run with **Spec Driven Development (SDD)** using
**GitHub Spec Kit**, with **Claude Code** as the agent.

## How to work

Every new feature starts with a spec in `specs/NNN-feature/spec.md`, generated by `/speckit.specify`
from `SPEC.md`. Code without a matching spec is reverted in review.

The canonical flow is `/speckit.specify` → `/speckit.clarify` → `/speckit.plan` → `/speckit.tasks`
→ `/speckit.analyze` → `/speckit.implement`. Skipping steps usually means rework.

Product decisions go in the spec. Technical decisions (stack, architecture) go in the plan. Do not
mix them.

## Non-negotiable principles (executable summary)

Full details in the [constitution](.specify/memory/constitution.md). Meeting all of them is an
explicit gate in `/speckit.plan`.

1. **Test-First (NON-NEGOTIABLE)**. TDD for all domain logic. Mandatory: a concurrency test proving
   that simultaneous holds on the same time never overbook.
2. **The LLM never writes (NON-NEGOTIABLE)**. The LLM proposes; only the deterministic tools write.
   `get_availability` is the only source of times.
3. **Simplicity & YAGNI**. No abstraction before two real consumers. Nothing from the out-of-scope
   list without a dedicated spec.
4. **Escalate when in doubt (NON-NEGOTIABLE)**. Never invent a time, insurance, price or clinical
   information. Escalate ambiguity, urgency, specialised procedures and ongoing treatment. Explicit
   confirmation before any commit.
5. **Traceability & LGPD (NON-NEGOTIABLE)**. `audit_log` of every write. Opt-in/opt-out, minimal
   data collection.

## Domain constraints

- **Pooled** capacity model: the patient does not choose a dentist; availability is a capacity
  counter, not resource matching. The `assigned` mode is out of scope.
- Google Calendar = source of truth for confirmed events. Postgres = capacity, holds, sync state.
  No direct call to the Calendar or WhatsApp without a testable port (`CalendarPort`,
  `MessagingPort`).
- The agent handles **routine** appointments only. Any other type is escalated.
- Every string a patient sees is in Brazilian Portuguese. Code and documentation are in English.

## Operating rules

- Do not edit files in `.specify/templates/`, `.specify/scripts/`, `.specify/workflows/` or
  `.claude/skills/` unless a Spec Kit command says so. They are framework infrastructure.
- Before changing the [constitution](.specify/memory/constitution.md), run `/speckit.constitution`.
  Editing it by hand breaks the Sync Impact Report.
- Build the deterministic layer with tests **before** plugging in the LLM. Integrations (Calendar,
  WhatsApp) sit behind ports, with fakes in the tests.
- Booking errors are explicit and handleable (e.g. `SlotUnavailableError`), never silent.
- When referring to files in answers, use clickable markdown links `[text](path)`.
